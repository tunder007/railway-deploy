The problem it solves

The backend runs on Railway with MySQL; env wiring is fiddly and secret-sensitive. Deploys need to be repeatable and to keep credentials out of logs and out of git. The motivating incident: a live Railway DB password was committed in plaintext to .claude/settings.local.json. This skill makes deploys reproducible and actively scans for that exact class of leak — masking any value it finds and recommending rotation.

Secret hygiene — the highlight

  • Scans for DB passwords, tokens, and credentialed connection strings in JSON and dotenv forms.
  • Skips placeholders (empty, ${VAR}, <...>, your_*, changeme…) to avoid noise.
  • Never prints a value — masked as first 2 chars + a fixed-length tail, so neither value nor length leaks.
  • Reproduces the real finding: .claude/settings.local.json → db-password; recommends rotation; confirms .env* gitignored.
  • A real deploy refuses to proceed while any secret is found.

Safety & determinism guarantees

  • Dry-run by default — no deploy without --deploy; the plan shows the exact command first.
  • Secret values never printed — masked at capture; absent from plans, JSON, and logs.
  • Deploy gate — refuses to run while preflight fails, env keys are missing, or any secret is found.
  • Idempotent migrations (Sequelize SequelizeMeta); safe to re-run.
  • Deterministic — no randomness/clock in the core; pure core in scripts/lib/run.mjs.
  • Offline self-test — never runs railway up/railway run or any mutating command; no network, no real secrets.
